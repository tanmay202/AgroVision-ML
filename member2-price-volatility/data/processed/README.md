## 2. Transformation Pipeline Stages

Every commodity follows the same leak-free 5-stage transformation pipeline:

1. **Stage 1: Cleaning (`data.clean_data`):**
   - Standardizes `Reported Date` to `YYYY-MM-DD`.
   - Forces numeric columns (`Modal Price`, `Arrivals`, `Min Price`, `Max Price`) to float.
   - Deduplicates identical `(Market Name, Variety, Reported Date)` records by preserving the latest entry.
   - Outputs: `{commodity}_cleaned.csv`.

2. **Stage 2: Time-Series Preparation (`data.prepare_timeseries`):**
   - Groups records by `(Market Name, Variety)` keys.
   - Sorts strictly by chronological date.
   - Generates forward target `future_modal_price` for valid observations within 1 to 7 calendar days.
   - Outputs: `{commodity}_timeseries.csv`.

3. **Stage 3: Feature Engineering (`features.*`):**
   - Computes historical lags, rolling statistics, calendar indicators, and arrival volume lags.
   - Enforces the **30-observation minimum history rule** (`_keep_model_ready_rows`).
   - Ensures `shift(1)` isolation to guarantee zero point-in-time leakage.
   - Outputs: `{commodity}_features_final.csv`.

4. **Stage 4: Time-Aware Partitioning (`evaluation.time_split`):**
   - Partitions data chronologically (e.g. 80% train / 20% test).
   - Enforces a temporal buffer between partitions to prevent target overlap.
   - Outputs: `{commodity}_train.csv` and `{commodity}_test.csv`.

5. **Stage 5: Volatility Target Derivation (`features.create_volatility_*`):**
   - Derives forward 5-observation price excursion labels (`LOW`, `MEDIUM`, `HIGH`).
   - Outputs: `{commodity}_volatility_train.csv`, `{commodity}_volatility_dataset_train.csv`, and `{commodity}_volatility_dataset_test.csv`.
